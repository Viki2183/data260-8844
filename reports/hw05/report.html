3.2 Retry Policy

The retry runner uses one initial attempt and two retries. Backoff delays are 5 ms and 10 ms. The reported latency measures the complete wall-clock duration, including failed attempts and backoff delays.

Reflection

I reviewed the blocked password-search run from agent_runs.jsonl. The user request was “Search for password records.” The agent selected the search tool with the input query “password” and limit 5. Before the database operation ran, the safety check examined the query. Because “password” is a credential-like term, the safety rule blocked the request. The tool returned the shared envelope with ok set to false, data set to null, and the error “safety rule blocked credential-like search.” The agent received that result and stopped with the model_final stop reason. Its final response explained that the request was blocked. The complete request, tool input, returned envelope, final answer, and stop reason were recorded in agent_runs.jsonl.

This run shows why safety must be enforced in the tool layer instead of relying only on the model. Even if the model selects a tool, the gateway can prevent sensitive requests from reaching the database. The shared response envelope makes the blocked result predictable for both the agent and automated tests. The offline safety test reproduced both an allowed package search and a blocked credential-like search. The separate MockModel test also verified that continuous tool requests stop at max_steps instead of creating an endless loop. Together, these checks made the agent easier to observe, test, and debug.
