3. Validation, Retries, and Fault Injection

The three rejected inputs were a blank search query, package ID zero, and the unsupported severity value Extreme. The retry policy allows two retries after the initial attempt and uses bounded exponential backoff.

5. Safety Rule and Ollama Agent

The safety rule blocks searches containing credential-like terms such as password, secret, token, or credential. A normal package search is allowed, while a credential-like search returns a structured blocked response without executing the tool.

The agent loop has a maximum step count. It records each request, selected tool, inputs, result, and final stop reason in agent_runs.jsonl.

Reflection

This homework connected a database-backed web application to MCP tools and a bounded local agent. The shared response envelope was one of the most useful design choices because successful results and rejected inputs followed the same structure. This made the offline tests easier to write and made errors easier to understand.

The retry experiment showed that retries help with temporary failures but cannot solve persistent failures. The 20% experiment achieved a 100% success rate, while the 50% experiment achieved 88%. For interactive use, a small retry budget keeps the application responsive. Batch processing could use more retries and longer delays.

The safety rule was also important. A model should not be able to search for credential-like data simply because it generated that request. The blocked-call test confirmed that safety is checked before tool execution. The maximum-step test prevented an endless tool loop. Finally, local Ollama inference showed that CPU execution may require longer timeouts and strict JSON output handling. These checks made the system more predictable than relying on the model alone.
